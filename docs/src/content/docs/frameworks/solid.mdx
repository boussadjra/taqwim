Two packages: `@taqwim/solid` for behaviour and accessibility with no styles, and
`@taqwim/solid-styled` for a calendar that already looks like one.

Both are thin bindings to [`@taqwim/calendar-core`](/reference/options/).
The state machine does the work; this package translates it into Solid.

## Common ground

Whatever the framework, the rendered DOM is the same. See
[Data attributes](/reference/attributes/) for the contract, and
[Theming](/guide/theming/) for how one stylesheet covers all five.

The option names are the same too — see
[Calendar options](/reference/options/). Porting an example between
frameworks is a matter of syntax, not of behaviour.

:::note[Fixed in 0.1.0-alpha.3]
Clicking a day used to be dropped in Solid, and only in Solid: `HijriCalendarGrid`
built its children from an expression that read the store snapshot, so any state
change rebuilt the whole grid. A browser focuses a button before it clicks it,
that focus is a state change, and Solid delegates `click` to the document — so
the click arrived at a button that had already been replaced.

The render-prop argument is now passed as an accessor, so the expression no
longer reads the store and the grid is updated in place. All twenty-eight shared
specs pass.
:::
