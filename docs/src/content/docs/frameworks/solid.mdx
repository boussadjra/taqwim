Two packages: `@taqwim/solid` for behaviour and accessibility with no styles, and
`@taqwim/solid-styled` for a calendar that already looks like one.

Both are thin bindings to [`@taqwim/calendar-core`](/taqwim/reference/options/).
The state machine does the work; this package translates it into Solid.

## Common ground

Whatever the framework, the rendered DOM is the same. See
[Data attributes](/taqwim/reference/attributes/) for the contract, and
[Theming](/taqwim/guide/theming/) for how one stylesheet covers all five.

The option names are the same too — see
[Calendar options](/taqwim/reference/options/). Porting an example between
frameworks is a matter of syntax, not of behaviour.

:::caution[Known gap]
Four of the twenty-eight shared end-to-end specs fail for Solid, and they fail
in a real browser rather than only in the suite: clicking a day cell can be
dropped. `HijriCalendarGrid` renders its children from an expression that reads
the store snapshot, so any state change rebuilds the whole grid subtree — and a
browser focuses a button before it clicks it, which is a state change. Solid
delegates `click` to the document, so by the time the click is dispatched the
button it was aimed at no longer exists.

The demo above is subject to it. It is not about controlled values; an earlier
version of this note said so and was wrong. The fix is to hand the child
function an accessor instead of a value, which means moving the render props off
`children` — an API change with its own pass. See
[`e2e/KNOWN-GAPS.md`](https://github.com/boussadjra/taqwim/blob/main/e2e/KNOWN-GAPS.md).
:::
