Two packages: `@taqwim/angular` for behaviour and accessibility with no styles, and
`@taqwim/angular-styled` for a calendar that already looks like one.

Both are thin bindings to [`@taqwim/calendar-core`](/reference/options/).
The state machine does the work; this package translates it into Angular.

## Full reference

The package README is the reference for this adapter and is kept next to the
code so the two cannot drift:

- [`packages/angular/README.md`](https://github.com/boussadjra/taqwim/blob/main/packages/angular/README.md) — the headless primitives, every prop, the keyboard model
- [`packages/angular-styled/README.md`](https://github.com/boussadjra/taqwim/blob/main/packages/angular-styled/README.md) — the themed components

## Common ground

Whatever the framework, the rendered DOM is the same. See
[Data attributes](/reference/attributes/) for the contract, and
[Theming](/guide/theming/) for how one stylesheet covers all five.

The option names are the same too — see
[Calendar options](/reference/options/). The `calendarSystem` option selects
[Umm al-Qura, Islamic Civil or Islamic TBLA](/guide/calendar-systems/).
Porting an example between frameworks is a matter of syntax, not of behaviour.

:::caution[Known gap]
The Angular adapter is not yet covered by the shared end-to-end suite: the
Analog Vite plugin cannot compile an Angular application under Vite 8. It is
verified by `ngc` with `strictTemplates` on every build, which checks every
component and template, but not at the DOM level. See
[`e2e/KNOWN-GAPS.md`](https://github.com/boussadjra/taqwim/blob/main/e2e/KNOWN-GAPS.md).

Angular 21 or later. Angular 22 requires TypeScript 6, which the rest of the
workspace is not on yet.
:::
